# 2026-08-03 ブレース / 柱脚 合成データ方針

前提は `2026-07-26-new-classes-final-state.md` と
`2026-07-26-new-classes-shortcut-learning-finding.md`。この文書は「Gemini で
合成データを作って新2部材の B/C/D 判定モデルを前に進める」ための方針を、
実データを読み直したうえで確定させる。

## 0. 出発点

測定済みの事実だけを並べる。

* 有効な干渉は**データ側の1件のみ**。負例 30-35% 追加で recall +0.060 / +0.097。
  損失関数・拡張・encoder・tiling など訓練/推論側の6件はすべてゼロか悪化。
* 失敗の機序は shortcut learning。学習画像は**全枚数が損傷あり**なので
  「部材がある」と「損傷がある」が完全相関し、モデルは前者を学んだ。
* 既存負例141枚は2倍反復で飽和済み。伸ばすには**新しい負例そのもの**が要る。
* 2026-05-26 の router 向け合成データは**正の効果が出なかった**
  （recall -0.0039）。原因は分布差・自動標注ノイズ・難例を外した・
  クラス精度への感度。同じ作り方を繰り返してはいけない。

## 1. 実データを読み直して分かったこと

`systems/gemini/scripts/extract_grade_reference_crops.py` で全 797 箱を
等級別に切り出し、コンタクトシートを目視した結果。

### 1.1 等級は箱の大きさとほぼ単調に対応する

画像面積に占める箱の割合：

| | B | C | D |
|---|---:|---:|---:|
| ブレース 中央値 | 0.87% | 6.93% | 16.4% |
| ブレース 25%超の箱 | 3.4% | 19.2% | **32.6%** |
| 柱脚 中央値 | 2.14% | 9.54% | 5.85% |
| 柱脚 25%超の箱 | 1.0% | 19.5% | 17.9% |

**箱のスケールが等級の代理変数になっている。** 合成正例を作るとき、
等級ごとの箱スケール規約を守らないと、外観が正しくても等級としては
偽ラベルになる。

### 1.2 等級の実体（目視、文書化された基準は社内に存在しない）

ラベルは客先 CVAT の `obj.names = B / C / D` のみで、判定基準書は
リポジトリのどこにもない。したがって**等級の意味は実データの crop に
しか存在しない**。文章でグレードを指示する生成は原理的に危険で、
実 crop による few-shot 条件付けが必須。

目視で読み取れた実体：

| 部材 | B | C | D |
|---|---|---|---|
| 柱脚 | コンクリートのひび割れ、角の軽微な欠け | 中程度の剥離・錆汁 | **露筋、腐食したアンカーボルト、大きな剥落・欠損、ベースプレートの隙間** |
| ブレース | 局所的な発錆、塗膜剥離、取合い部の微細ひび | **部材レベルの弛み・変形（箱は構面全体）** | 座屈・破断・ガセットプレートの孔食、部材レベル |

### 1.3 これが最も重要な発見

**ブレースの C は、多くが「部材そのものの弛み・変形」で、箱は
ブレース構面全体を覆っている。** 局所的な欠陥テクスチャではない。

二つの帰結がある。

1. **ブレース C では「部材を検出する」と「損傷を検出する」が、
   箱のレベルでほぼ同一の課題になっている。** 標注の作られ方から
   そうなっている。shortcut learning の原因は負例欠如だけでなく、
   C の標注規約そのものにもある。負例が唯一効いた理由もこれで説明が付く
   ——健全なブレースにも同じ形の箱が引けてしまう以上、「箱を引かない」
   例を見せる以外に区別を教える手段がない。
2. **ブレース C を「小領域に損傷テクスチャを描き込む」方式で合成するのは
   誤り。** C の合成は部材の幾何を変える編集でなければならない。

## 2. 方針：3本の合成ライン

### S1 — 反事実負例（損傷除去）★最優先

有損傷画像の箱領域を**健全な状態に修復**し、同一シーン・同一照明・
同一構図の負例を作る。ラベルは空ファイル。

```text
実正例 (293 / 224)  --損傷除去-->  合成負例 (最大 293 / 224)
```

これを最優先にする理由：

* **測定済みで唯一効いた干渉（負例）を、飽和している141枚の 3.7 倍に伸ばす。**
* **箱を一切必要としない。** 5月の失敗原因#2（自動標注ノイズ）を構造的に回避。
* 生成物が正例と**対になる**。同じ部材・同じ現場・同じ画角で
  「損傷あり／なし」の反事実ペアができるので、
  element↔damage 相関を最も直接的に破壊できる。
* 「健全な部材」は「特定等級の損傷」より生成が容易で、Gemini の失敗余地が小さい。

### S2 — 位置指定の損傷注入（正例）

健全な部材画像の**指定 mask 内**に損傷を描き込む。箱は mask から決まるので
Gemini に箱を描かせない。等級は 1.2 の実 crop で few-shot 条件付けし、
箱スケールは 1.1 の等級別規約に合わせる。

種画像：実負例141枚 + S1 の出力。

優先順位は枯渇している等級から：

| 対象 | 現状の箱数 | 合成の適合度 |
|---|---:|---|
| 柱脚 D（露筋・腐食ボルト・剥落） | **39** | ◎ 局所外観編集、inpainting が最も効く |
| 柱脚 C | **82** | ○ |
| ブレース D | 92 | △ 幾何変形を含む |
| ブレース C | 239 | ✕ 部材レベル変形。S2 では作らない |
| B（両部材） | 146 / 199 | 作らない（過剰） |

**ブレース C/D の部材レベル変形は S2 の射程外。** ここは実データ追加でしか
埋まらない、と客先に言い切れる材料になる。

### S3 — 全画像テキスト生成（対照アームのみ）

5月と同じ作り方。単独では効かないことが測定済みなので、少量だけ回して
「今回も比較した」と示すための対照に留める。予算を割かない。

## 3. 全ラインに課す4つの制約

1. **正例と負例は同じ処理経路を通す。** 合成負例だけが Gemini の再エンコードを
   経ると、モデルは「滑らかな修復痕＝負例」を新しい shortcut にする。
   実正例にも同一の round-trip（同一 API 経由の無編集再生成、または
   同一の再エンコード）を通し、両者の低レベル統計を揃える。
   `2026-07-26-new-classes-final-state.md` の negcrop / tiled 失敗が
   まさにこの経路不一致だった。
2. **箱を Gemini に生成させない。** 箱は必ず mask 由来。
3. **合成は train のみ。** test は `data/frozen/new_classes_20260725.lock.json`
   で凍結済みのまま触らない。
4. **等級別の箱スケール規約を守る**（1.1）。

## 4. 評価側の先行課題

合成データの効果は現在の評価系では**測れない可能性が高い**。

* test は 83 / 72 箱。1 TP = recall 0.012-0.014、F1 差 0.03 未満は分解不能。
  合成データの期待効果量はこの帯に入りうる。→ 凍結5-fold での集計が必要。
* **誤警報が未計測。** frozen test は損傷ありの画像しか含まないので、
  「健全な部材に対して黙っていられるか」——負例が直すはずの当の性質——が
  測れない。S1 の効果は現行指標ではゼロに見える恐れがある。
  → 健全部材のみの held-out 誤警報ベンチを先に作る。

## 5. 人手が要る1点

141枚の実負例には**本物の未標注損傷が混ざっている**
（`f-00189` 露筋、`f-00322` 剥落、`f-00203` 腐食した柱脚）。
これらを負例として使うと真の損傷の抑制を学習する。S1 の種としても不適。
`outputs/rfdetr_new_classes/empty_label_audit/` のコンタクトシートで
triage が必要。`column_base_NEGATIVE.jpg` の目視でも数枚は明らかに錆・汚損を
伴っており、機械的な一括採用は危うい。
