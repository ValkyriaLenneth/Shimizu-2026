# 2026-08-04 ラベルノイズの発見と、十六件の否定的結果

一日分の記録。**KPI は動いていない**（ブレース 0.590 / 柱脚 0.514 のまま）。
動いたのは診断の精度である。十六の方向が失敗し、その失敗の形が揃って
一点を指した。最後に見つけた方向（BRL 系）のみが単一モデルで効果を示し、

前提は `2026-08-04-synthetic-negatives-and-failed-interventions.md`。

## 0. 最重要：ラベルが不完全である

Gemini による全数監査（`systems/gemini/scripts/audit_annotation_completeness.py`）。
**注釈済みの学習画像**に対して損傷インベントリを取り、GT 箱と突き合わせた。

| | 監査画像 | GT 箱 | 判定が見つけた領域 | **箱で覆われていない** | 未注釈損傷を含む画像 |
|---|---:|---:|---:|---:|---:|
| 柱脚 | 179 | 248 | 341 | **168 (49%)** | **87 / 179 (49%)** |
| ブレース | 235 | 394 | 310 | 154 (50%) | 86 / 235 (37%) |

30 枚標本での 56% が全数 179 枚で 49%。**小標本の偶然ではない。**

### 規約と漏れの区別

判定器は既知の過読傾向を持つ（客先が空ラベルとした画像の 69% に損傷を見る）。
したがって単純な比率では規約と漏れを分離できない。**種類別の内部比較**で分ける：

| 損傷種別 | GT 箱あり | 箱なし | 漏れ率 | 判読 |
|---|---:|---:|---:|---|
| **剥落** | 17 | 8 | **32%** | 標注不一致 |
| **ひび割れ** | 8 | 7 | **47%** | 標注不一致 |
| 腐蝕/錆 | 2 | 14 | 88% | 規約（客先は表面錆を等級付けしない） |
| 破断 | 0 | 4 | 100% | 規約または過読 |
| 露筋 | 0 | 1 | 100% | 同上 |

**剥落とひび割れは客先が明確に等級付けする種別**（17 箱・8 箱が現に存在する）
なのに、同じ剥落の 32%、同じひび割れの 47% が箱を持たない。規約なら
「付ける／付けない」のどちらかであって、半分だけ付けることはない。
腐蝕は逆に綺麗で、2 対 14 は「客先は表面錆を損傷程度として扱わない」を意味する。

### なぜこれが本日の全失敗を説明するか

同一種の損傷が、ある時は正例、ある時は背景として学習される。監督が自己矛盾
していれば、検出器の合理的な応答は**その種別に中間的なスコアを与えること**で
ある。これは測定された症状そのものに一致する：

* 閾値を下げた時の recall 上限 0.875 / 0.940 に対し、運用点で 0.514 / 0.590
* 真の損傷のスコアが誤検出のスコアより低い
* 合成データを足すほど悪化する（矛盾が比例して増幅される）

### 二カテゴリで問題が違う

| | 剥落/ひび割れの漏れを持つ画像 | 未注釈領域の主な種別 |
|---|---:|---|
| 柱脚 | 48 / 179 (**27%**) | 腐蝕 82、剥落 22、ひび割れ 35 |
| ブレース | 11 / 235 (**5%**) | 腐蝕 43、**座屈 39**、**破断 36**、変形 10 |

**ブレースにラベルノイズはほぼ無い。** その未注釈領域の 55% は座屈・破断・
変形——部材レベルの幾何状態であり、客先もこれらを箱にしていない。
ブレースの困難は**注釈体系そのもの**にある：「部材全体が変形している」を
局所の箱で表現しようとしている。この結論は独立した三つの証拠と一致する
（方針文書の「C は構面全体の箱」、S1 の幾何幻覚、copy-paste が有害）。

## 1. 前提の訂正：交付済み四カテゴリとデータ量は同じ

`data_split.json` の実数：

| | train | valid | test | 交付 F1 |
|---|---:|---:|---:|---:|
| 天井 / 内壁 / RC壁 / RC柱（各） | **242** | 28 | **31** | 0.72-0.86 |
| ブレース | 235 | 58 | 58 | 0.554 |
| 柱脚 | 179 | 45 | 45 | 0.556 |

文書が繰り返す「交付済みは 605-966 枚」は誤りで、**実際は各 242 枚**。
学習量はほぼ同じである。差は二点：

1. **test が 31 枚 対 58/45 枚。** 小さい test は選択バイアスが強く働き、
   同じ valid==test 規約下で数字が高く出る。限界事項 5 が既に警告している。
2. **交付済み四種は全て「単一部材のひび割れ」**（各 config の note に明記）。
   平面上の線状欠陥であり、B/C/D も幅と長さでほぼ決まる。新二種は一つの
   等級ラベルに複数材質・複数形態の損傷が混在する。

**データ量の問題ではなく、課題の難易度が違う。**

## 2. 失敗した十六方向

すべて凍結 split・同一プロトコル（recall-first で epoch 選択、15 値の閾値
グリッド、match IoU 0.229）で測定。

| 系統 | 方向 | 柱脚 | ブレース |
|---|---|---|---|
| 訓練側 | 解像度 896 | −0.111 | −0.036 |
| | RFDETRSmall | P>=0.60 到達せず | −0.096 |
| | 正則化 drop_path 0.25 + wd 1e-3 | −0.153 | −0.156 |
| | 正則化 drop_path 0.08 | −0.084 | −0.132 |
| | 統合事前学習 | −0.181 | −0.120 |
| 合成データ | S1 反事実負例（置換） | 到達せず | — |
| | copy-paste 正例 ×2 | +0.014 | −0.120 |
| | copy-paste 正例 ×5 | −0.125 | — |
| | copy-paste 対称 | −0.181 | −0.072 |
| | S5 生成健全シーン | −0.056 | — |
| 推論側 | crop 分類器で再スコア | F1 0.561→0.150 | — |
| | 検出器自身の誤検出で再学習 | F1 0.561→0.141 | — |
| 注釈側 | Gemini による補注釈 | −0.097 | −0.096 |
| 推論集約 | **2 モデル + TTA** | **+0.055** | **+0.144** |

### 正則化が効かないことの意味

小値（0.08）でも大値（0.25）でも基線を下回る。**パラメータ選択の誤りではなく
方向が無効**。そしてこれはラベルノイズ仮説と整合する——正則化が対処するのは
「真のパターンへの過学習」であって「矛盾ラベルへの過学習」ではない。信号自体が
自己矛盾している時、容量を絞れば一貫した部分すら学べなくなる。

### 三度繰り返した同じ誤り

**領域レベルの判別能力は、箱レベルの定位精度に変換されない。**

1. 凍結 DINOv2 + ロジスティック回帰は、健全／損傷の crop を AUC 0.924 /
   0.857、recall 0.951 / 0.921 で分離する。しかし検出器の候補箱（1 画像あたり
   23 個、多くは同一部材上のずれた窓）に適用すると precision 0.082、
   best F1 は 0.561 から 0.150 に落ちた。
2. 負例を「検出器自身の誤検出」に替えて再学習しても 0.141。**学習データの
   問題ではなく、真の検出箱と誤検出箱が特徴空間で分離不能**だからである。
   これは識別の失敗ではなく**定位の曖昧性**であり、crop レベルのモデルを
   外付けしても解けない。
3. Gemini の箱は、判定器が「正しく当てた」領域でさえ人手 GT との IoU 中央値
   0.354-0.454、四分位下限は 0.22。補注釈は座標ノイズの注入になった。

VLM 全般の限界と一致する：Gemini 2.5 Pro の RF100-VL ゼロショット
mAP50:95 は 13.3。**「あるか」は判定できるが、人手水準の箱は出せない。**

## 3. 評価プロトコルの誤り三件（本日発見・修正済み）

本日の前半の数値はこれらにより**実験側に不利に歪んでいた**。

1. **epoch を mAP で選んでいた。** config は `primary_metric: test/recall` と
   明記し、さらに「自動の checkpoint_best_total.pth は mAP で選ばれるので
   使うな」と警告している。`val/recall` 列は存在した。両者の選ぶ epoch は
   実際に異なる（ctrl80: mAP→50/51/66、recall→56/55/29）。
   → `systems/rfdetr/scripts/select_and_score_recall_first.py` に手順を固定。
2. **閾値グリッドが 5 値だった**（0.20-0.40）。交付基線は 15 値（0.05-0.50）。
   低閾値域が探索されず recall が人為的に抑えられていた。修正後 ctrl80 は
   0.389 → 0.458。
3. **medium モデルに 30 epoch を適用した。** RFDETRSmall のピークが ep15 で
   あることから一般化したが、柱脚の medium は ep30 時点で val/recall が
   単調上昇中（未収束）。ctrl80 が 0.333 に留まり、S1 置換実験一巡が無効化。

### データ汚染バグ（修正済み）

`build_relabeled_view.py` が `os.link` でハードリンク複製した後、ラベルを
その場で書き換えていた。**inode を共有するため元データも書き換わる**。
汚染は relabel → neg ビュー → 基礎データセットと三層に伝播し、凍結 lock の
`train.boxes_by_grade.D` が 29 → 33 になった。paired から再構築し
`freeze --check` の一致を確認済み。書き込み前に `unlink()` するよう修正。

## 4. 唯一有効だったもの：推論集約

新データなし・再学習なしで、**WBF（Weighted Boxes Fusion）**により融合。
NMS は重なりクラスタの最高スコア箱以外を捨てるため、一つのビュー／モデルだけが
見つけた真陽性が失われる。WBF は座標を加重平均し確信度を累積するので残る。
**recall 優先の要件に対して、この非対称性が正しい向き。**

ブレース（交付基線 → 2 モデル + 水平反転 TTA）:

| 精度下限 | 基線 | 2モデル | **2モデル+TTA** |
|---|---:|---:|---:|
| P>=0.60 | 0.458 | 0.518 | **0.602** |
| P>=0.50 | 0.590 | 0.627 | **0.663** |
| P>=0.40 | 0.627 | **0.711** | 0.699 |
| best F1 | 0.554 | 0.581 | **0.606** |

柱脚（2 モデル）: P>=0.40 で 0.611（基線 0.556）、P>=0.30 で 0.667（0.597）。
**未達。** TTA は柱脚では効果が薄い。

単一モデル + TTA だけでもブレース P>=0.50 で 0.651 に達する。計算量は
どちらも 2 倍だが、**単一モデルなら重みが一つで済む**ため運用上はこちらが安い。

代償は推論計算 2-4 倍。オフラインのバッチ処理なら通常許容範囲。

## 5. 唯一効いた学習側の手法：疎な注釈のための損失（BRL 系）

第 0 節の診断に直接対応する唯一の系統。**Background Recalibration Loss**
(Zhang et al.) は、背景とされたが確信度の高いサンプルの勾配を反転させる。
報告された増分：欠落 20.6% で +7.2 mAP、39% で +6.4、65% で +10.7、
COCO 50% 除去で +9.0。**柱脚の実測 27% はこの範囲内。**

RF-DETR の `loss_labels`（ia_bce 分岐）では、未マッチ query は

```python
neg_weights = prob ** gamma
```

を負う。**確信度が高いほど強く背景へ押される。** ラベルが完全なら正しい
（自信のある誤検出を抑える）が、不完全なら最悪である——モデルが最も確信して
いる query こそ未注釈の損傷であり、そこに最大の負の勾配がかかる。
**これが「真の損傷が誤検出より低いスコアを持つ」の生成機序。**

`systems/rfdetr/scripts/brl_patch.py` に三段階を実装（monkey patch）：

| モード | 主張の強さ |
|---|---|
| `ignore` | 背景重みをゼロに。「漏れかどうか分からない」——監査が確立した内容そのもの |
| `flip` | 論文原版。正例として学習。「これは漏れである」——健全部材への発火率 95.7% を踏まえると強すぎる |
| `pu` | 背景重みを 0.25 に。「背景ラベルは約 75% しか信頼できない」——実測漏れ率に最も近い |

### 完全評価の結果（凍結 test、15 値グリッド、recall-first で epoch 選択）

**ブレースは改善、柱脚は改善せず。**

ブレース（単一モデル、追加の推論コストなし）:

| 精度下限 | 交付基線 | BRL-ignore 0.35 | 差 |
|---|---:|---:|---:|
| P>=0.55 | 0.542 | **0.590** | +0.048 |
| P>=0.50 | 0.590 | **0.639** | +0.049 |
| P>=0.45 | 0.614 | **0.663** | +0.049 |
| P>=0.40 | 0.627 | **0.675** | +0.048 |
| P>=0.30 | 0.687 | **0.699** | +0.012 |

六点すべて正、幅は 0.048 前後で安定。単点の揺れではない。P>=0.60 には到達しない
（高信頼の未マッチ query の背景圧を外すため、真の誤検出も罰されなくなり精度上限が削れる）。

柱脚: P>=0.40 で 0.528、P>=0.30 で 0.542。同バッチ対照 ctrl80 と誤差帯内で並び、
交付基線には届かない。

### 変体スイープ：`flip` は両カテゴリで壊滅

| 変体 | 柱脚 P>=0.50 | ブレース P>=0.50 |
|---|---|---|
| ignore 0.20 | 到達せず（P>=0.30 で 0.611） | — |
| **ignore 0.35** | 0.486 | **0.639** |
| ignore 0.50 | 0.431 | — |
| **flip 0.35** | **全域で到達せず** | **全域で到達せず** |
| pu 0.35 | 0.472 | 0.361 |

**論文原版の `flip` を採ってはならない。** 「この高信頼検出は注釈漏れである」と
断定する操作だが、本モデルは未見の健全部材に 95.7% 発火する。その誤検出を
正例として学習させれば誤検出が増えるだけで、実測どおり PR 曲線は P>=0.30 にも届かない。
保守版（`ignore`＝背景圧をゼロにするだけ）を選んだ判断は正しかった。
`pu`（背景重みを 0.25 に残す）も中途半端で両カテゴリとも劣る。

### 機序は「注釈漏れの修復」ではない

| | 剥落/ひび割れの漏れ率 | BRL の効果 |
|---|---:|---|
| 柱脚 | **27%** | なし |
| ブレース | **5%** | **+0.048** |

**向きが逆である。** 漏れが最も多い柱脚で効かず、ほぼ無いブレースで効いた。
したがって BRL がブレースで効く機序は漏れの修復ではなく、
**「構面全体の箱」対「局所 query」の構造的不整合の緩和**と考えるのが妥当である。
同一部材上の多数の query が箱に一致せず背景として強く押されるが、
それらが見ているのはまさにその損傷部材である。

この解釈が正しければ、ブレースにより適合するのは Part-aware Sampling
（部品が全体に属する類型で分類損失を無視する手法）であり、未検証である。

**柱脚の 27% の注釈漏れは依然として未解決。** BRL では解けず、Gemini による
補注釈も箱の精度不足で失敗した（人手 GT との IoU 中央値 0.354-0.454）。
人手での補注釈が必要である。

### 推論集約との併用

BRL と集約は直交する（一方は学習、他方は推論時の統合）。ブレースで併用すると
P>=0.40 で 0.723（基線 0.627）まで伸びるが、P>=0.60 では 0.434 に落ちる。
**BRL は精度上限を削って低精度域の再現率を買う操作**であり、recall 優先の要件とは
向きが合うが、無条件に足せるものではない。運用点ごとに選ぶこと。
