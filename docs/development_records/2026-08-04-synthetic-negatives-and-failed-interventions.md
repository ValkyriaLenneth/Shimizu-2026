## 1. 誤警報を初めて測った。0% と 95.7%

限界事項 2（誤警報未測定）を埋めた。`systems/rfdetr/scripts/measure_false_alarms.py`。

| プール | n | 交付閾値での発火率 | ピーク中央値 |
|---|---:|---:|---:|
| 実負例（141 枚のうち brace 分、**学習に使用済み**） | 59 | **0.0%** | 0.000 |
| S1 反事実負例・train 由来 | 18 | 94.4% | 0.768 |
| S1 反事実負例・**test 由来** | 5 | **100%** | 0.452 |

同じ現場・同じ部材・同じ画角で、**損傷だけを消した**画像に対して
モデルは 95.7% 発火する。最高スコアの検出は「損傷が元あった位置」と
IoU 0.96-0.98 で一致する。

**実負例での沈黙は暗記であって、「損傷がない」という概念の獲得ではない。**
負例介入が +0.060 に留まった理由がこれで説明できる。

合成痕跡による説明は完全には排除できないが、**23 枚中 7 枚は
モデルが書き換えていない画素の上で発火**しており（masked paste-back は
枠内のみ書き戻す）、そのうち `e-00362` は test 由来で 0.939。
JPEG 再圧縮は部材形状を生成しないので、これらは構造そのものへの反応である。

**帰結：S1 負例は hard negative として価値がある。** 実負例は誤り 0%
＝勾配が残っていない。合成負例は誤り 95.7% ＝全部が現在の誤りである。
用量曲線が 31-35% で飽和し 48% で有害になる以上、**追加ではなく置換**が
正しい使い方になる（負例比率を変えずに情報量だけ入れ替える）。
`build_rfdetr_negatives_view.py` に `--synthetic-pool` / `--synthetic-replace`
を追加した。

## 2. S1 の適用境界：修復が「表面の操作」で済むか

ブレースの yield は **39%**（pass 5 / review 4 / reject 14）で、
柱脚の 76%（pass 18 / review 18 / reject 11）の半分。
しかし本質は yield ではなく、**失敗の質**にある。

**鋼部材では、モデルは損傷を消さずに部材を作り替える。**

* `e-00085` 破断したブレース → ボルト付きスプライスプレートに置換
* `e-00034` 交差部 → 実体の三角ガセットプレートが出現
* `f-00254`（柱脚・鋼）腐食したロッド → 別形状の部材に変化

3 枚とも QC を **pass** している。ゲートは「損傷が消えたか」を訊くので、
**作り替えられた部材は満点を取る**。

これは修復失敗より悪い。画像は「損傷なし」のラベルで学習に入るのに、
実データに存在しない部品が写っている。モデルがその架空の部品を
「健全の証拠」として学びうる。

境界は部材種別ではなく**修復の性質**で引ける：

| 損傷 | 「修復」が意味するもの | 結果 |
|---|---|---|
| コンクリートのひび割れ・剥落 | 表面を埋める（テクスチャ操作） | 幾何が保たれる、使える |
| 鋼の破断・変形・断面欠損 | 物理的には**部材交換** | 幾何が再構築される、使えない |

柱脚の yield が高いのは、損傷がコンクリート主体だからにすぎない。

### QC ゲートに幾何の問いが無かった理由と、その直し方

`JUDGE_PROMPT` は 2 問（damage_removed / residual_at_repair_site）だけで、
部材の同一性を訊いていなかった。ただし**既存プロンプトに 1 問足すだけでは効かない**。

ゲートは 08-03 の校正結果に従い、髪の毛ほどのひびを見るために
**修復窓を原寸で切り出して**判定する。その窓の中に部材の輪郭は写らない。
同じ判定器・同じ問いでも：

```text
切り出し窓で訊く : structure_preserved = true    （見えないので）
全画面で訊く     : structure_preserved = false
                   "Splice plate and bolts added."  confidence 0.95
```

**残留判定は局所原寸を、幾何判定は全画面を必要とする。両立しない。**
そこで幾何は別呼び出しに分離した：`systems/gemini/scripts/check_geometry_preserved.py`。

08-03 の教訓どおり、**判定器を使う前に既知解で校正**した：

| 画像 | 目視 | 判定 |
|---|---|---|
| `e-00085` | 幾何改変 | false ✓ "bolted splice plate assembly ... added" |
| `e-00034` | 幾何改変 | false ✓ "metal plate added at the intersection" |
| `f-00327` | 幾何保持 | true ✓ |

3/3 一致。

なお v1 QC の集計では **steel の可用率が最も高い**（ブレース 4/4、柱脚 86%）。
これは反証ではなく欠陥の証拠である——**部材を徹底的に作り替えた編集ほど
「損傷が消えたか」で満点を取りやすい**。

## 3. 無効だった介入 2 件（データ側ではなく訓練側）

いずれも凍結 split・同一プロトコルで測定。

| 介入 | ブレース (R@P>=0.50) | 柱脚 (R@P>=0.60) |
|---|---:|---:|
| 交付基準 | **0.590** | **0.514** |
| 解像度 896（576 から） | 0.554 (−0.036) | 0.403 (−0.111) |
| RFDETRSmall（medium から） | 0.494 (−0.096) | P>=0.60 に到達点なし |

### 解像度が効かない理由は診断済みだった

**train split で測ると**：

| | train recall | test recall | train 最小四分位の見逃し | test 同 |
|---|---:|---:|---:|---:|
| ブレース | **0.995** | 0.590 | **0 / 98 = 0%** | 9 / 20 = 45% |
| 柱脚 | 0.827 | 0.514 | 19 / 61 = 31% | 12 / 17 = 71% |

ブレースは学習画像 394 箱のうち 2 箱しか落とさず、**最小の 98 箱を一つも
落としていない**。小物体の知覚能力は制約ではない。解像度を上げても
汎化しない問題は直らない。事前登録した予測（「ブレースには無効」）は当たり、
「柱脚には小幅の改善」は外れた。

### 容量を下げると悪化する ＝ 制約は容量過剰ではなくデータ量

train 0.995 / test 0.590 を見て「容量過剰による過学習」と判断し
RFDETRSmall を試したが、**両カテゴリとも悪化**した。柱脚に至っては
閾値グリッド全体で precision 0.60 に到達しない。

したがって **235 / 179 枚という規模では、どの容量でも訓練集合は暗記される**。
容量を削っても汎化する特徴を学ぶようにはならず、学ぶべきものまで学べなくなる。
同じ理屈で**正則化強化も期待できない**。

**制約はデータ量そのもの**であり、実データが増やせない以上、合成が唯一の道になる。

## 4. epoch 数：80 は 3-5 倍の無駄

`val/mAP_50` のピーク位置：

| 実験 | ピーク epoch |
|---|---:|
| RFDETRSmall ブレース | **15** |
| RFDETRSmall 柱脚 | 31 |
| 柱脚 交付 checkpoint | 16 |
| 896 ブレース | 77（例外。ただし失敗した実験） |

交付構成の 80 epoch は「過学習させてから一番マシな epoch を選ぶ」形になっており、
それを新実験にそのまま持ち込むと 1 実験あたり 3-5 倍の GPU 時間を捨てる。
**以後 30 epoch を既定**とする。柱脚 30 epoch は約 6.5 分で終わる。

## 5. JSCA 追加 45 枚は使えない

`extra_unlabelled_images`（ブレース 29 / 柱脚 16）は「唯一未使用の実データ」
として誤警報ベンチの素材候補だったが、**使えない**：

* 寸法 ~250x180 px（学習画像は 360x270 〜 640x480）
* 「柱脚」等の日本語テキストが焼き込まれた**講習資料のスクリーンショット**
* 判定器は 4/4 を損傷ありと判定（講習教材なので当然）
* `e-00383` は `column_base/f-00329` と sha256 一致

誤警報ベンチの素材は S1 反事実負例に一本化する。test 由来の S1 負例は
学習に使えない（シーン漏洩）ので、そのまま held-out ベンチに回すのが
無駄がない。
