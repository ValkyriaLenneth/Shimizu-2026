# 门控引入的新依赖:路由器在 13-14% 的图上定位失败  (2026-08-16)

## 为什么查这个

交付配置今天新增了一个它早上还不依赖的组件:2026-07-07 的五类路由器。
门控丢弃落在构件之外的检测框,而**若路由器找不到构件,门控就静默失效**。

门控被刻意设计为宽容:**未定位到构件的图完全不做门控**,所以定位失败
永远不会造成漏检(这正是四项 recall 一个数未变的原因)。但它确实静默地
损失了门控的收益,而此前没有人看过那是哪些图。

## 实测

| | 张数 | 中位分辨率 | 亮度中位 | 宽高比中位 | 门控前 箱/张 | 门控后 | 发火 |
|---|---:|---:|---:|---:|---:|---:|---:|
| **冻结测试集** | | | | | | | |
| 定位成功 | 39 | 0.31MP | 121 | 1.33 | 3.00 | 2.90 | 97% |
| 未定位 | 6 | 1.01MP | 122 | 1.33 | 2.67 | 2.67 | 100% |
| **健全柱脚照片** | | | | | | | |
| 定位成功 | 25 | 3.15MP | 123 | 1.33 | 2.00 | **1.76** | 84% |
| 未定位 | 4 | 2.53MP | 104 | 1.33 | 1.00 | 1.00 | **100%** |

## 三条结论

### 1. 失败没有可识别的模式

未定位组与定位成功组在亮度(122 vs 121)、宽高比(1.33 vs 1.33)上几乎相同,
分辨率**略高**而非略低。**不是"小构件"或"暗光"这类可预警的类别。**

这对交付是好消息:现场同类图上门控失效的比例应与此处相当
(测试集 13%、健全图 14%),而不会集中在某个可预见的子群并造成系统性盲区。
但也意味着**无法事先识别哪张图会失效**。

### 2. 门控恰在最需要它的那一小群图上失效

健全图中未定位的 4 张**全部发火(100%)**,定位成功的 25 张为 84%。
这 4 张本身出框少(1.00 对 2.00 箱/张),却每张都至少发一个框。

**因此 86% / 1.66 箱-张是对约 86% 图像有效的平均值,不是对每张图的保证。**

### 3. 门控的收益几乎全部来自误报侧

    冻结测试集   3.00 -> 2.90 箱/张(删掉 3%)
    健全图       2.00 -> 1.76 箱/张(删掉 12%)

与设计意图一致 —— 门控删的是构件外的框,而受损图上模型本就更多地在构件上开火。
这也解释了为什么门控的 precision 主张(0.383 -> 0.395)过不了留出验证
(`10_router_gate.md`):它在受损图上删掉的框太少,precision 的变化主要是
少量清理的结果,而非稳定效应。**采纳门控的理由始终是误报侧,这条实测支持了
当初的判断。**

## 给客户说明中应包含的一句

> 约 13-14% 的柱脚照片上,系统无法定位构件,此时空间过滤不生效(设计如此,
> 以免造成漏检)。这部分图像没有可识别的共性,但其误报率高于过滤生效的图像。
> 报告的误报改善应理解为对约 86% 图像有效的平均值。

## 降低路由器阈值:已测,反而更差

零训练的替代路径是降低路由器自身的阈值(现 0.30),让它在更多图上定位到构件。
实测 0.30 -> 0.05:

| 路由阈值 | 测试覆盖 | 健全覆盖 | 构件框占幅 | P | 发火 | 箱/张 |
|---:|---:|---:|---:|---:|---:|---:|
| **0.30** | 87% | 86% | 74% | **0.395** | **86%** | **1.66** |
| 0.20 | 89% | 93% | 73% | 0.347 | 90% | 2.28 |
| 0.15 | 89% | 97% | 74% | 0.347 | 90% | 2.31 |
| 0.10 | 91% | 97% | 74% | 0.345 | 90% | 2.31 |
| 0.05 | 96% | 97% | 78% | 0.345 | 90% | 2.41 |

**覆盖率确实上升(健全图 86% -> 97%),但误报恶化(1.66 -> 2.31 箱-张),
precision 掉 0.05。**

事先设想的两种失效都没有发生:构件框占幅稳定在 73-78%(门控没有名存实亡),
四项 recall 一个数未变(低阈值没有定位到错误区域)。

真正的原因是第三种:**门控取的是所有柱脚框的并集**。低阈值下路由器在同一张图上
返回更多框,并集覆盖的区域变大,于是**原先落在构件外、会被删掉的误报,
现在落进了扩大后的区域**。

    健全覆盖 86% -> 97%    多覆盖 3 张图
    箱/张   1.66 -> 2.31   在原本已覆盖的 25 张图上,每张多留约 0.6 个框

**用少数图的覆盖,换多数图的过滤强度,是笔亏本买卖。**

`0.30` 是当前配置下的正确取值。**这条零训练路径已关闭。**

## 仍未做的事

重训路由器可以提高低阈值下的定位精度,但会引入**新的训练依赖**,
而当日结论是训练侧在当前数据下无正收益(`13_delivery_protocol_training_check.md`)。

上表的机制解释还指向一个未测的变体:**门控改用最高分单框而非并集**。
若"区域变大"确实是主因,单框应能在保留覆盖率的同时恢复过滤强度。
