# B/C 边界审计:重叠真实存在,但 recall 仍是有意义的量  (2026-08-16 晚)

## 为什么查

当日三条独立测量都把剩余的误报问题指回 B 级(`19_geometry_exhausted.md`),
而 baseline 配置记载语料中 11 处等级矛盾里有 6 处是柱脚 B-vs-C。那个计数来自
更早的审计,**从未对照过框本身的样子**。

这直接关系到待客户决定的取舍:他们被问"B 级 recall 能否从 0.702 降到 0.681",
而这个问题预设了 **B 标签稳定到让 0.702 成为一个真实的量**。
若 B 与 C 抽自重叠分布,任一方的 recall 都在部分地报告标注者的分歧。

## 标注框几何(全部 320 个已标注框)

| 级 | 框数 | 面积占比 p25 / 中位 / p75 | 宽高比中位 |
|---|---:|---|---:|
| B | 199 | 0.0088 / **0.0214** / 0.0548 | 0.84 |
| C | 82 | 0.0254 / **0.0977** / 0.2300 | 1.01 |
| D | 39 | 0.0116 / 0.0585 / 0.1408 | 1.45 |

    B 落在 C 的四分位区间内: 43%
    C 落在 B 的四分位区间内: 32%

## 三条结论

### 1. 重叠真实,但分布是分开的

B 与 C 的面积中位数相差 **4.6 倍**(0.0214 对 0.0977)。43% / 32% 的交叉率说明
标注者在中间地带确实会分歧,**但这不是"随机贴标签"** —— 是分布分离、尾部重叠。

### 2. 模型的混淆与标注的重叠吻合

交付配置在冻结集上:命中 51、位置对等级错 12、位置错 62。等级错的构成:

    预测B 实为C  5     预测D 实为C  3     预测C 实为D  2
    预测B 实为D  1     预测C 实为B  1

**B<->C 互错 6 次,占等级错的 50%**,而 B/C 正是几何上最接近的一对。
**模型在标注者会分歧的地方分歧** —— 这是一致的表现,不是额外的模型缺陷。

### 3. 因此「B recall 0.702」仍是有意义的量

若 B/C 完全不可分,recall 就是在报标注噪声。实测是分布分离、尾部重叠,
所以 0.702 描述的主要是真实检测能力,**只有边缘部分受标注一致性影响**。

## 对待决取舍的影响:问题变得更容易回答

    B 从 0.702 降到 0.681 = 47 个 B 框中的 1 个
    而 43% 的 B 框落在 C 的四分位区间内 —— 边界地带的框数远多于 1

**被让出的那一个框,极可能正在标注者自己也会分歧的地带。**
这个取舍付出的不是"确定的真损伤",而是"一个连人也未必判为 B 的框"。

于是待客户回答的问题可以从

    要不要牺牲 1 个 B 框,换取现场工作量降 24%?

改写为

    要不要坚持一个边界本就模糊的 0.70?

后者更容易回答,且更如实地描述了取舍的性质。

## 顺带:门控删的确实只是位置错

`09_what_the_errors_are.md` 记录的位置错 64、等级错 12,是**并集门控**时代的数。
单框门控下位置错降到 **62**,等级错**不变(12)**。
门控一个等级错都没碰,与其设计意图完全一致。
