# 九个推理参数在当前形态下的完整重扫  (2026-08-16 晚)

## 为什么重扫

交付配置在当日经历了四次形态变化(融合参数修正 -> 加翻转视图 -> 加门控 ->
门控改单框)。每次变化之后,**先前定下的参数都成了在旧形态下选出的值**。

本项目为此付出过代价:315 个集成成员子集被否,只因为它们是在为另一配置选定的
`wbf_iou` 下评估的(`01_fusion_params.md`)。故对全部九个参数逐一重扫。

## 结果:九个参数,一处改动

| 参数 | 扫描范围 | 结论 | 形状 |
|---|---|---|---|
| 成员级 `floor` | 0.05-0.20 | **0.10** | 两侧断崖,唯一可行 |
| `wbf_iou` x 权重 | 0.20-0.60 x 1:1/1:2/1:3 | **0.40 / 1:2** | 15 组中误报最低 |
| `conf_type` | max / avg / box_and_model_avg | **max** | 两个平均类无达标点 |
| 门控形态 | 硬 / 软(线性、幂、带底) | **硬** | 八个软变体全部更差 |
| 门控取法 | 并集 / 最高分单框 | **单框** ← 改动 | 留出 92.5% 更好 / 0.0% 更差 |
| 门控强度 `g` | 0.3-0.8 | **0.5** | 0.4-0.5 平台,0.6 断崖 |
| 构件框外扩 | 0.00-0.30 | **0.05** ← 改动 | 0.00 断崖 |
| 路由器阈值 | 0.30-0.05 | **0.30** | 降低使并集膨胀 |
| 门控方向 | 正向 / 反向 | **仅正向** | 反向物理上不成立 |

两处改动(门控取法、外扩)已采纳并各自过了检验;其余七项确认无需改动。

## 两个形状值得单独记下

### `floor` 是唯一没有平台的参数

`wbf_iou`、`g`、外扩都有平台,`floor` 两侧都是断崖:

    0.05  precision 0.325,误报 1.66 箱-张(过多低分框进入融合)
    0.10  precision 0.408,误报 1.41
    0.15  无四项达标点(真损伤进不了融合)

原因:**它是唯一决定"框能否进入融合"的参数。** 后续所有环节
(融合、门控、阈值)都只能处理已进入的框 —— **进不来的框,后面救不回来。**

### `conf_type` 的平均类在四输入下彻底失效

两个平均规则连四项达标点都找不到,不是"稍差"。四个输入里翻转视图是原图视图的
近似副本:真实损伤通常被四个视图都检出,平均后变化不大;但**边缘的真损伤只被
其中一两个检出**,平均把分数除以四,压到任何阈值之下,recall 就塌了。

`max` 保留最有把握的那个意见,边缘检出得以存活。**加翻转视图放大了 max 与
平均的差异,而不是削弱它** —— 当初在两输入下选 max 的理由,在四输入下更强。

## 这份表的用途

**下一个接手的人可以直接引用这些设定,不必怀疑其来历。** 每个值都有当前形态下的
测量支撑,不是从旧配置继承的。若将来上游再变(换成员、换视图、换门控),
应当重跑本目录下对应的脚本,而不是沿用本表。
