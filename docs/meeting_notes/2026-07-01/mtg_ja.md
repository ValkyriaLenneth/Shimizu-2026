## 4. Pipeline における検出枠統合ロジック

お客様向けには、Pipeline の後処理を以下のようにご理解いただくと分かりやすいと考えます。

> モデルが複数の候補枠を出力した後、システム側のルールによって、表示しやすく、かつリスクを見落としにくい形に整理します。

これらのルールはモデル判断を置き換えるものではありません。実画像において発生しやすい重複、重なり、境界付近の判定、表示上の見やすさといった課題を補正するための後処理です。

### 4.1 ルール統合が必要な理由

モデルの生出力をそのまま最終表示に使わない理由は、主に以下の通りです。

- 同じ損傷に対して複数の重複枠が出ることがあります。
- 異なるモデルが同じ位置に対して異なる解釈を出すことがあります。
- 部材境界付近の検出枠が自動識別領域から一部はみ出すことがあり、過度に厳しく削除すると妥当な検出まで失われます。
- 下流モデルが出力しない場合でも、最終表示が空にならないようにする必要があります。

本節では、Pipeline 内で実施している最適化処理として、「どの枠を残すか」「どの枠を重複として除くか」「どの枠を表示上まとめるか」を整理します。

### 4.2 IoU / IoA の基本概念

![IoU / IoA 説明図](assets/iou_ioa_explanation.png)

IoU は、2つの枠がどの程度重なっているかを示す指標です。1 に近いほど、2つの枠がほぼ同じ対象を指していると解釈できます。そのため、「2つの検出枠が同じ対象を示しているか」を判断する際に適しています。

IoA は、ある枠の面積のうち、別の枠にどの程度覆われているかを示す指標です。大きな枠の中に小さな枠が含まれるようなケース、例えば小さな損傷枠が大きな部材領域内にあるかを確認する際に有効です。

### 4.3 自動識別領域によるフィルタリング

現在の処理は以下の通りです。

- 下流モデルは、まず画像全体に対して推論を実行します。
- その後、自動識別モデルが出力した部材領域を用いて結果をフィルタリングします。
- 以下のいずれかを満たす検出枠を保持します。
  - 検出枠の中心点が部材領域内にある。
  - 検出枠自身の面積のうち、少なくとも 50% が部材領域内にある。

主要パラメータ：

```text
region_filter_mode = center_or_ioa
region_filter_ioa_threshold = 0.50
```

パラメータの意味：

- 中心点ルールは、位置が明確な検出枠を保持するための条件です。
- 50% IoA ルールは、境界付近の検出枠を過度に削除しないための条件です。
- 中心点のみで判断すると、境界付近の損傷が削除されやすくなります。一方で、まったくフィルタリングしない場合は、明らかに対象部材外の枠も後続処理に流れてしまいます。

したがって、この処理は「妥当な検出を誤って削除しないこと」と「明らかな誤検出を抑えること」のバランスを取るためのものです。例えば、損傷が壁と柱、または壁と天井の境界付近にある場合、検出枠が完全には部材領域内に収まらなくても、保持すべきケースがあります。

### 4.4 損傷候補の重複除去

現在、損傷候補の重複除去には NMS を使用しています。

簡潔に言うと、NMS は以下の処理です。

- 重複している候補枠を削除します。
- 座標を融合する処理ではありません。
- 複数の枠を平均して新しい枠を作る処理でもありません。

NMS の最小処理フローは以下の通りです。

![NMS フロー説明](assets/nms_flow_explanation.png)

主要パラメータ：

```text
same_grade_iou_threshold = 0.90
cross_grade_iou_threshold = 0.95
prefer_higher_grade = true
```

ルールの意味：

- 同一等級の枠が大きく重なっている場合、重複候補を削除します。
- 異なる等級の枠については、より高い重なり度でなければ削除しません。これにより、B/C/D 間の有効候補を早期に削除しすぎることを避けます。
- 優先順位としては、より高い損傷等級を優先します。同一等級の場合は confidence の高い候補を保持します。
- `0.90` および `0.95` は比較的保守的な設定であり、2つの枠が非常に近い場合にのみ重複除去を行います。そのため、リスク情報を早期に削りすぎない方針となっています。

### 4.5 最終表示レイヤーでの統合

最終表示レイヤーでは、候補をさらに表示向けに整理します。

- 同一系統の近い枠は、少数の表示項目にまとめます。
- 異なるクラスの候補を無理に1つへ改判定することはしません。
- 同じ位置に複数の解釈がある場合は、候補情報として保持します。

以下は、最終表示レイヤーにおける整理の流れを示したものです。

![最終表示レイヤー統合説明](assets/final_display_merge_step_explanation.png)

主要パラメータ：

```text
cluster_same_family.iou_threshold = 0.35
cluster_same_family.ioa_threshold = 0.70
collapse_ambiguity.enabled = false
```

パラメータの影響：

- `iou_threshold = 0.35`：同一系統の候補に一定以上の重なりがある場合、同じグループとして扱います。これにより、同じ損傷周辺に複数の表示枠が出ることを抑えます。
- `ioa_threshold = 0.70`：ある枠の大部分が別の枠に覆われている場合も、同一グループとして扱います。大きな枠が小さな枠を含むケースに対応するための条件です。
- `collapse_ambiguity.enabled = false`：クラス解釈に曖昧さがある候補を、無理に1つの結果へ統合しません。

この処理の目的は、画面上の見やすさを確保しつつ、曖昧な候補情報を失わないことです。例えば、同じ位置が壁類とも RC柱とも解釈できる場合、システムは候補情報を保持し、フロントエンド表示または人手確認に回せる状態にします。

## 5. 現時点の結論と今後の対応

### 5.1 現時点の結論

- 5クラス自動識別モデルの学習は完了しています。
- 全体 Precision は `0.9039` であり、目標値 `0.90` を上回っています。
- 新規クラスは統一された自動識別モデルに取り込まれています。
- 新規クラスについては、現時点では自動識別段階までの対応であり、下流の損傷検出モデルは未構築です。
- Pipeline の統合ロジックは階層ごとに説明可能であり、各処理に対応する主要パラメータも明確です。

### 5.2 今後の対応

新規クラスの損傷判定用データのラベル付けが完了次第、ブレースおよび柱脚向けの下流損傷検出モデルの学習に着手します。

下流ラベルを待つ間に、`ブレース` の Recall 改善も並行して検討可能です。現時点では、課題はモデル閾値だけではなく、データ品質・データ量の影響が大きいと考えています。

- `ブレース` は形状および撮影角度のばらつきが大きい。
- Gemini の自動枠は、細長い斜め部材に対して境界が不安定になる場合がある。
- 有効な学習枠数がまだ十分とは言えない。
- テストセットのサンプル数が少なく、指標が変動しやすい。

したがって、次の対応としては、`ブレース` の人手確認、Gemini アノテーション枠の一部修正、遠景・遮蔽・斜め部材など典型的な追加サンプルの整備を優先することを推奨します。その後、再学習またはクラス別閾値調整を行う方針が妥当です。
