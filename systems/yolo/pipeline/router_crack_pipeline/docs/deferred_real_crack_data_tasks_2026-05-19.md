# 依赖真实裂缝数据/业务标注的延期事项

日期：2026-05-19

以下事项暂不阻塞当前系统集成。原因是它们需要真实裂缝/损伤标注、用户验收口径或更完整业务数据，不能只靠当前 router 数据和单图 smoke test 得出可靠结论。

## 1. 裂缝模型效果评估

需要真实裂缝标注或上一期标准测试集。

待完成：

- 按 `天井 / 内壁 / RC壁 / RC柱` 分别评估 B/C/D 检测效果。
- 评估 router 接入后，端到端裂缝检测相对旧流程的变化。
- 统计 router 正确时和 router 错误时的裂缝检测指标差异。

## 2. 下游判别框重叠策略验收

当前已实现可配置 NMS 骨架，但业务规则需要确认。

待确认：

- 同一裂缝被多个下游模型检测到时，是否只保留最高置信度。
- B/C/D 等级冲突时，优先保留更严重等级，还是优先保留更高置信度。
- 重叠阈值应按 IoU、IoA，还是结合裂缝长宽比调整。

## 3. 墙类正式策略

当前可运行策略：

```text
壁类 -> inner_wall + rc_wall 并行 debug
```

待确认：

- 正式输出是否允许同时运行内壁和 RC壁模型。
- 如果两个模型都输出结果，是否合并、择优，还是保留 wall_subtype=unknown。
- 是否可从元数据获取内壁/RC壁上下文，替代视觉判断。

## 4. Router 中低置信度 fallback

当前状态：

- 高置信度：正常调用对应判别模型。
- 无检测：输出 unknown。
- 中低置信度：已保留 TODO warning。

待确认：

- 中低置信度时是否允许调用多个候选判别模型。
- 多模型 fallback 的输出是否进入正式报告。
- fallback 的最大模型调用数量和延迟预算。

## 5. 端到端业务指标

需要完整测试集和用户口径。

待完成：

- 用户可接受的误路由率。
- unknown 输出比例上限。
- 单图平均耗时上限。
- 多构件图像中重复结果的可接受展示方式。
